Medipal

A chatbot for HKU University Health Service questions that answers only from a fixed set of official pages, and shows where every answer came from.

AILT9019 student project, HKU. Not an official HKU service, and not a medical service.

2The problem

Students ask the University Health Service the same kinds of question again and again. Where is the clinic? Which number do I call? Can I claim this back? The answers exist, but they are spread over several pages of the UHS website, and finding the right one takes longer than it should.

A general chatbot looks like an easy fix, but it can state an opening time or a reimbursement rule that is simply wrong. For a health service that has a real cost: someone turns up at the wrong place, or misses a three-month claim deadline.

Some messages should not get a chatbot answer at all. A person describing heavy bleeding, asking for a sick note to support a deadline extension, or saying they feel hopeless needs a different kind of response.

Who it is for. HKU students who need UHS information. The corpus includes student-specific topics such as student benefits, referrals and reimbursements.

We set out to build something that is useful for UHS information, cannot make things up, and is clear about when to hand over to a person.

3What we built

Medipal is a single web page with a fixed corpus of eight entries taken from seven UHS pages, retrieved on 20 October 2026. To answer a question it finds the best-matching entry and shows that entry's text unchanged, with its source. It does not write new sentences.

Key features

Every answer is cited. Each reply names its source page, links to it, and states the retrieval date, because the corpus is a snapshot and may go out of date.

It declines to guess. If no entry matches well enough, Medipal says the information is not in its database and gives the UHS contacts.

It is private. The whole thing runs in the browser. There is no login and no API key, and nothing typed is stored or sent anywhere.

It accepts Chinese questions. They are matched through keyword aliases, although replies are in English.

4How it works

  1. Safety guards run first.Before any searching, the question is checked against five safety routes (listed below). If one fires, Medipal gives its fixed reply and stops.
  2. Each corpus entry is scored.Filler words such as “the” and “please” are dropped. Each remaining word earns points depending on how it matches an entry.
  3. Two thresholds decide.An entry is used only if its score is at least 3 and it covers at least 40% of the question's words. A one-word question needs just 2 points.
  4. Answer or fall back.If an entry passes, its text is shown with source and date. If none does, Medipal gives a fixed “not in my database” reply with official contacts.

The scoring

4phrase keyword3keyword2title word or near-keyword1word in page text

Small typos and word endings are tolerated, so “reimbursements” still matches “reimbursement”. The coverage threshold is what stops a single lucky word from triggering an answer. For example, “What are the opening hours?” has no strong match in any entry, so it correctly returns “not found” instead of a loosely related one.

Every reply also lists the top passages it considered, which makes the choice easy to check.

Why not a language model?

In this setting we wanted every answer to be traceable and testable. With word-based retrieval, each reply can be explained by a score and a source, nothing can be invented, and no server or key is needed. The cost is that an unusual paraphrase can come back as “not found”. We accepted that trade.

6Run it yourself

Medipal is one HTML file. It needs no installation, no login, no API key, and no internet connection once you have the files.

  1. Download the files.On the GitHub repository, choose Code, then Download ZIP, and unzip it.
  2. Open the chatbot.Double-click medipal-chatbot.html. It opens in your browser.
  3. Ask something.Type a question, click a suggestion, or click one of the eight corpus entries in the sidebar.
git clone https://github.com/y-ku-ku/Medipal.git
cd Medipal
# then open medipal-chatbot.html in your browser:
#   macOS:   open medipal-chatbot.html
#   Windows: start medipal-chatbot.html
#   Linux:   xdg-open medipal-chatbot.html
Running the test suites

Under the input box there are two small buttons, “run self-tests” and “run unseen test”. If you opened the file from your computer, the browser asks you to choose self-tests.csv or unseen-tests.csv; pick the file with that exact name. Each question is replayed through the chat and a results panel appears when it finishes.

Serving it over HTTP instead

If you serve the folder over HTTP(S), the tests load by themselves, and adding #tests to the address runs the self-tests when the page opens.

python3 -m http.server 8000
# then visit http://localhost:8000/medipal-chatbot.html#tests

7What a successful run looks like

When Medipal is working you should see all of the following.

  • The page opens at once with no sign-in, no key and no errors. You see a greeting, eight entries in the sidebar and a row of suggested questions.
  • After a short typing pause, a question the corpus covers returns that entry's text, with a source line and the retrieval date.
  • A question outside the corpus returns the “not in my database” message with UHS contacts, not a guess.
  • An emergency or distress message produces a red safety card straight away, pointing to 999 and human help.
  • Running the self-tests ends with 61 of 61 passing, with every group marked ACCEPT.

Test results

Each test case is graded on three things, and all three must hold. It must reach the right route (a corpus entry, the fallback or a safety route). A corpus answer must be verbatim corpus text with its source, URL and date. And the reply must name an official channel, such as a UHS number, email, link or 999.

8Limitations

  • No opening hours or fees. They are not in the corpus, so Medipal says so and gives contacts.
  • English replies only. Chinese questions are understood through keyword aliases, but answers stay in English.
  • Words, not meaning. Retrieval matches words, so an unusual paraphrase can miss the right entry.
  • A dated snapshot. The corpus was retrieved on 20 October 2026 and does not update itself. Please confirm anything important with UHS directly.
